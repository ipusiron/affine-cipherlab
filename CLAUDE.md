# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Overview

Affine CipherLab - an educational web tool for the affine cipher: encryption and decryption with a mapping table, a brute-force attack over all 312 keys ranked by an English score, and a Learn tab. Japanese and English UI, light and dark themes. Part of the "100 Security Tools with Generative AI" project (Day049).

## Architecture

All scripts are plain (non-module) scripts so that the page works from `file://`. Each script puts one object on `globalThis`.

- **index.html**: header (language and theme buttons), WAI-ARIA tabs (Encrypt, Decrypt, Brute force, Learn), separate key and input alert boxes per tab (aria-live), Learn articles for `ja` and `en` (`data-lang`, toggled with `hidden`). Meta CSP without `'unsafe-inline'`; no style attributes, inline scripts or handlers. Static text carries `data-i18n` / `data-i18n-attr`
- **js/affine-core.js** (`AffineCore`): pure logic, no DOM. `encrypt`/`decrypt` convert only A–Z/a–z through a lookup map and keep everything else. `parseKey(raw, 'a'|'b')` accepts integers only (a 1–25 with a `notCoprime` warning, b 0–25). `egcd` returns the table rows (r, q, s, t). `bruteForce(cipher)` tries 312 keys on the first `SCORE_LETTERS` (2,000) letters and ranks by `englishScore` = adjacent-pair log-likelihood + `WORD_WEIGHT` (4) × common words (2+ letters, `COMMON_WORDS`, 275); `close` when the top-two margin < `CLOSE_MARGIN` (3). `MAX_TEXT` 100,000
- **js/english-data.js** (`AffineEnglish`): generated by `tools/build-english.mjs` from `tools/corpus/train-pg1342.txt` (letters only, add-one smoothing, 3 decimals). Do not edit by hand
- **js/accuracy.js** (`AffineAccuracy`): generated by `node tools/evaluate.mjs write` from `tools/corpus/eval-pg98.txt` (300 trials per length, seed 20261004). Used for the short-text note
- **js/messages.js** (`AffineMessages`): all strings in Japanese and English (same keys and placeholders). `t(key, vars, lang)`
- **js/i18n.js** (`AffineI18n`): language from `?lang=` → saved (`affine-cipherlab-lang`) → browser language; `applyStaticText`
- **js/theme-init.js / theme.js** (`AffineTheme`): theme applied before paint, toggle saved as `affine-cipherlab-theme`
- **js/script.js**: UI only. Keys are synced between Encrypt and Decrypt; mapping rows use `data-m`; persistent highlight (`highlighted`) and a short pulse (`pulse`) are CSS classes
- **css/style.css**: color tokens on `:root`; the OS dark block and `[data-theme="dark"]` must stay identical (tested). Crack table stacks below 600px using `data-label`

## Development Commands

- `npm test` — node:test, no dependencies, Node 22+. Runs in GitHub Actions on push and pull requests
- `node tools/build-english.mjs` — rebuild the pair table; `node tools/evaluate.mjs tune|eval|write` — choose weights on the training text, print or write accuracy
- `node tools/make-corpus.mjs <pgXXXX.txt> <out>` — make an excerpt from a Project Gutenberg text (originals are not stored here)

## Testing

- `test/core.test.js`: known answers from Python (inverses, encryption, egcd rows), key parsing, mapping table, preprocessing
- `test/crack.test.js`: corpus hashes, generated table equals the generator output, brute-force ranking, `close`, scoring prefix, word weight effect
- `test/html.test.js`, `test/messages.test.js`, `test/i18n.test.js`, `test/contrast.test.js`, `test/format.test.js`: CSP and markup, dictionaries, language choice, contrast 4.5:1 in light and dark, line length and LF
- `test/readme.test.js`: both READMEs (same headings), YAML structure, examples / inverse / accuracy tables against the implementation, claims (99.3%, 56.2%, about 160,000 letters, 275 words), directory tree, images (4 each)

## Key Implementation Notes

- Never use `innerHTML`; never set inline styles (CSP has no `'unsafe-inline'`)
- Do not reject non-ASCII input; only A–Z/a–z are converted
- README numbers are recomputed by tests — update them from the tools, not by hand. README states only what is true for the current version
- Japanese strings do not put half-width spaces between Japanese and alphanumeric characters
