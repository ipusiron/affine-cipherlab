# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Overview

Affine CipherLab - an educational web tool for the affine cipher: encryption and decryption with a mapping table, a brute-force attack over all 312 keys ranked by an English score, solving by hand (from 2–6 known pairs, a known word (crib), and E/T guesses from the most frequent letters), a Learn tab with an inverse calculator, and a Practice tab (five questions per question number). Japanese and English UI, light and dark themes. Part of the "100 Security Tools with Generative AI" project (Day049).

## Architecture

All scripts are plain (non-module) scripts so that the page works from `file://`. Each script puts one object on `globalThis`.

- **index.html**: header (language and theme buttons), WAI-ARIA tabs (Encrypt, Decrypt, Brute force, Solve by hand, Learn, Practice), preset key buttons, pair rows 1–2 in the HTML (3–6 are added by the script), separate key and input alert boxes per tab (aria-live), Learn articles for `ja` and `en` (`data-lang`, toggled with `hidden`). Meta CSP without `'unsafe-inline'`; no style attributes, inline scripts or handlers. Static text carries `data-i18n` / `data-i18n-attr`
- **js/affine-core.js** (`AffineCore`): pure logic, no DOM. `encrypt`/`decrypt` convert only A–Z/a–z through a lookup map and keep everything else. `parseKey(raw, 'a'|'b')` accepts integers only (a 1–25 with a `notCoprime` warning, b 0–25). `egcd` returns the table rows (r, q, s, t). `bruteForce(cipher)` tries 312 keys on the first `SCORE_LETTERS` (2,000) letters and ranks by `englishScore` = adjacent-pair log-likelihood + `WORD_WEIGHT` (4) × common words (2+ letters, `COMMON_WORDS`, 275); `close` when the top-two margin < `CLOSE_MARGIN` (3). `MAX_TEXT` 100,000. `solveFromPairs(p1, c1, p2, c2)` solves c1 − c2 ≡ a·(p1 − p2) (unique if the difference is coprime to 26; g candidates otherwise; reasons `samePair`, `contradiction`, `noSolution`, `noValidA`, `several`). `solveFromKnown(pairs)` solves from the first pair and the first pair with a different plaintext letter, then filters by the other pairs (`checks`; stops when no key is left; reasons add `notLetter` with `pair`, `contradiction` with `conflict`, `eliminated`). `cribSearch(cipher, crib)` places the crib at every letter position: letter pattern (`samePattern`), key from two pairs, then the remaining letters (`rejected` counts, keys grouped with `positions`, ranked by English score); `cribPairsAt` gives the pairs at a position (up to 6). `makeQuiz(seed)` (1–`QUIZ_MAX_SEED`) makes five questions with `quizRandom` (xorshift32); Q5 uses `PROVERBS` (26 sentences); `checkQuizAnswer` checks answers. `frequencyHypotheses` tries 30 E/T guesses from the top `HYPOTHESIS_LETTERS` (6) letters. `linkParams` / `urlWithoutText` read `#text=` first and clear it
- **js/english-data.js** (`AffineEnglish`): generated by `tools/build-english.mjs` from `tools/corpus/train-pg1342.txt` (letters only, add-one smoothing, 3 decimals). Do not edit by hand
- **js/accuracy.js** (`AffineAccuracy`): generated by `node tools/evaluate.mjs write` from `tools/corpus/eval-pg98.txt` (300 trials per length, seed 20261004). Used for the short-text note and the frequency-guess note (`frequency`); `crib` holds the README crib table (THE and THAT)
- **js/messages.js** (`AffineMessages`): all strings in Japanese and English (same keys and placeholders). `t(key, vars, lang)`
- **js/i18n.js** (`AffineI18n`): language from `?lang=` → saved (`affine-cipherlab-lang`) → browser language; `applyStaticText`
- **js/theme-init.js / theme.js** (`AffineTheme`): theme applied before paint, toggle saved as `affine-cipherlab-theme`
- **js/script.js**: UI only. Reads `#text=` (or `?text=`) on load into the Brute force tab and removes it with `history.replaceState`; links to Day009 with `#text=` (up to 5,000 characters). Keys are synced between Encrypt and Decrypt; mapping rows use `data-m`; persistent highlight (`highlighted`) and a short pulse (`pulse`) are CSS classes
- **css/style.css**: color tokens on `:root`; the OS dark block and `[data-theme="dark"]` must stay identical (tested). Crack table stacks below 600px using `data-label`

## Development Commands

- `npm test` — node:test, no dependencies, Node 22+. Runs in GitHub Actions on push and pull requests
- `node tools/build-english.mjs` — rebuild the pair table; `node tools/evaluate.mjs tune|eval|freq|crib|write` — choose weights on the training text, print accuracy (brute force, frequency guesses or cribs), or write js/accuracy.js
- `node tools/make-corpus.mjs <pgXXXX.txt> <out>` — make an excerpt from a Project Gutenberg text (originals are not stored here)

## Testing

- `test/core.test.js`: known answers from Python (inverses, encryption, egcd rows), key parsing, mapping table, preprocessing
- `test/solve.test.js`: solving from two pairs (known answers from brute force in Python), `solveFromKnown` against all 312 keys, frequency guess order, URL input
- `test/crib.test.js`: `cribSearch` against all 312 keys at every position, letter pattern, errors, pairs at a position, 100,000 letters
- `test/quiz.test.js`: question number 1 is fixed, answers checked by separate calculations, every sentence comes back first by brute force
- `test/crack.test.js`: corpus hashes, generated table equals the generator output, brute-force ranking, `close`, scoring prefix, word weight effect
- `test/html.test.js`, `test/messages.test.js`, `test/i18n.test.js`, `test/contrast.test.js`, `test/format.test.js`: CSP and markup, dictionaries, language choice, contrast 4.5:1 in light and dark, line length and LF
- `test/readme.test.js`: both READMEs (same headings), YAML structure, examples / inverse / accuracy / frequency-guess / crib tables against the implementation, claims (99.3%, 56.2%, about 160,000 letters, 275 words, the practice example), directory tree, images (8 each)

## Key Implementation Notes

- Never use `innerHTML`; never set inline styles (CSP has no `'unsafe-inline'`)
- Do not reject non-ASCII input; only A–Z/a–z are converted
- README numbers are recomputed by tests — update them from the tools, not by hand. README states only what is true for the current version
- Japanese strings do not put half-width spaces between Japanese and alphanumeric characters
